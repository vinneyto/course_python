# Практический курс Python: от основ к собеседованиям

Это курс-тренажёр: вместо длинных лекций — небольшие задачи с постепенным
ростом сложности. Первые упражнения закрепляют строки и встроенные коллекции,
затем курс знакомит с ленивыми вычислениями и только после этого переходит к
файлам, конкурентности и сети. У каждой задачи есть условие, заготовка с `TODO`
и тесты на основные и краевые случаи.

## Быстрый старт

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
pytest 00_basics/01_strings          # первая простая задача
pytest 02_iterators/02_running_total # одна задача по генераторам
pytest                               # весь курс (до решений тесты падают — это нормально)
```

Заменяйте `raise NotImplementedError` в `task.py`, не изменяя публичные
сигнатуры. Проверить стиль и типичные ошибки можно командой `ruff check .`.

## Рекомендуемый маршрут

| № | Тема | Задачи | Что тренируем |
|---|---|---:|---|
| 0 | `00_basics` | 4 | строки, списки, словари и множества |
| 1 | `01_data_structures` | 2 | heap, hash map, сложность алгоритмов |
| 2 | `02_iterators` | 4 | `iter`/`next`, `yield`, ленивость, декораторы |
| 3 | `03_files` | 2 | потоковый I/O, контекстные менеджеры, atomic write |
| 4 | `04_concurrency` | 2 | потоки, очереди, порядок результатов, исключения |
| 5 | `05_asynchronous` | 4 | корутины, `gather`, fan-in/fan-out, отмена |
| 6 | `06_networking` | 1 | TCP framing и частичные чтения |
| 7 | `07_typing_and_metaprogramming` | 1 | дескрипторы и валидация |

### Как проходить первые темы

1. В `00_basics` решайте задачи по порядку: каждая посвящена одной встроенной
   структуре и требует лишь цикла или нескольких методов.
2. В `02_iterators` сначала вручную используйте `iter()` и `next()`, затем
   напишите простой генератор и только после этого переходите к батчам и
   декоратору повторных попыток.
3. В `05_asynchronous` начните с одной корутины и `await`, продолжите
   конкурентным `asyncio.gather`, а уже затем беритесь за ручное управление
   задачами, очереди, отмену и backpressure.

Для каждой задачи сначала запустите её тесты и прочитайте ошибку. Реализуйте
самый прямой вариант, добейтесь зелёных тестов, а затем обсудите альтернативы и
сложность. В продвинутых задачах отдельно спрашивайте: кто владеет ресурсом, как
распространяются ошибки и что происходит при отмене.

## Правила задач

* Разрешена стандартная библиотека, если условие не говорит обратного.
* Тесты — исполняемая часть контракта; README объясняет намерение, но детали
  типов и исключений закреплены тестами.
* Не подгоняйте решение под конкретные значения тестов: возможны скрытые тесты.
* Для задач с потоками и asyncio избегайте `sleep` как способа синхронизации.
