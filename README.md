# Практический курс Python: от основ к собеседованиям

Это курс-тренажёр: вместо длинных лекций — небольшие задачи с постепенным
ростом сложности. Строки и каждая встроенная коллекция вынесены в отдельную
тему с несколькими упражнениями. Затем курс знакомит с итераторами и только
после этого переходит к алгоритмам, файлам, конкурентности и сети. У каждой
задачи есть условие, заготовка с `TODO` и тесты на основные и краевые случаи.

## Быстрый старт

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate                 # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
pytest 01_strings/01_normalize_words      # первая простая задача
pytest 05_iterators/02_running_total      # одна задача по генераторам
pytest                                    # до решений тесты падают — это нормально
```

Заменяйте `raise NotImplementedError` в `task.py`, не изменяя публичные
сигнатуры. Проверить стиль и типичные ошибки можно командой `ruff check .`.

| 1 | `01_strings` | 3 | методы строк, символы, разбиение и срезы |
| 2 | `02_lists` | 3 | циклы, фильтрация, вложенные списки |
| 3 | `03_dictionaries` | 3 | счётчики, группировка, объединение данных |
| 4 | `04_sets` | 3 | уникальность, пересечение, объединение и разность |

| 7 | `07_files` | 2 | потоковый I/O, контекстные менеджеры, atomic write |

### Как проходить первые темы

1. Пройдите отдельные темы строк, списков, словарей и множеств по порядку. В
   каждой сначала решается одна операция, а затем данные приходится
   фильтровать, группировать или сопоставлять.
2. В `05_iterators` сначала вручную используйте `iter()` и `next()`, затем
   напишите простой генератор и только после этого переходите к батчам и
   декоратору повторных попыток.
3. После алгоритмов, файлов и потоков в `09_asynchronous` начните с одной
   корутины и `await`, продолжите конкурентным `asyncio.gather`, а уже затем
   беритесь за ручное управление задачами, очереди, отмену и backpressure.

Для каждой задачи сначала запустите её тесты и прочитайте ошибку. Реализуйте
самый прямой вариант, добейтесь зелёных тестов, а затем обсудите альтернативы и
сложность. В продвинутых задачах отдельно спрашивайте: кто владеет ресурсом, как
распространяются ошибки и что происходит при отмене.

## Правила задач

* Разрешена стандартная библиотека, если условие не говорит обратного.
* Тесты — исполняемая часть контракта; README объясняет намерение, но детали
  типов и исключений закреплены тестами.
* Не подгоняйте решение под конкретные значения тестов: возможны скрытые тесты.
* Для задач с потоками и asyncio избегайте `sleep` как способа синхронизации.
